## 3. Тест дизайн — сонголт ба утгын хүснэгт

### 3.1 Тестлэх функц

`POST /registrations` API нь оюутныг хичээлд бүртгэх үйлдлийг гүйцэтгэнэ. Бүртгэл амжилттай болохын тулд оюутан системд бүртгэлтэй, идэвхтэй, сонгосон хичээл системд бүртгэлтэй, мөн хичээлийн урьдач нөхцөлийг хангасан байх шаардлагатай.

Тест дизайн хийхдээ API-ийн оролтын нөхцөлүүдийг сонголтуудад хувааж, сонголт бүрд төлөөлөх утга тодорхойлон, тэдгээрийн хослолоос тестийн спецификациуд гаргав.

### 3.2 Сонголтуудын хүснэгт

| №   | Сонголт                          | Боломжит утга           | Тайлбар                                                           |
| --- | -------------------------------- | ----------------------- | ----------------------------------------------------------------- |
| 1   | `studentID`-гийн хүчинтэй байдал | Идэвхтэй оюутан         | Оюутан системд бүртгэлтэй, төлөв нь `active`                      |
| 2   | `studentID`-гийн хүчинтэй байдал | Идэвхгүй оюутан         | Оюутан системд бүртгэлтэй боловч төлөв нь `inactive`              |
| 3   | `studentID`-гийн хүчинтэй байдал | Байхгүй оюутан          | Оюутны ID системд бүртгэлгүй                                      |
| 4   | Оюутны үзсэн хичээлүүд           | Урьдач нөхцөл хангасан  | Оюутан шаардлагатай бүх хичээлийг үзсэн                           |
| 5   | Оюутны үзсэн хичээлүүд           | Урьдач нөхцөл хангаагүй | Оюутан шаардлагатай хичээлүүдээс заримыг эсвэл алийг нь ч үзээгүй |
| 6   | `courseID`-гийн хүчинтэй байдал  | Байгаа                  | Хичээл системд бүртгэлтэй                                         |
| 7   | `courseID`-гийн хүчинтэй байдал  | Байхгүй                 | Хичээл системд бүртгэлгүй                                         |
| 8   | Хичээлийн урьдач нөхцөл          | Бүгд үзсэн              | Оюутан шаардлагатай бүх урьдач хичээлийг үзсэн                    |
| 9   | Хичээлийн урьдач нөхцөл          | Огт үзээгүй             | Оюутан шаардлагатай урьдач хичээлүүдийн алийг ч үзээгүй           |
| 10  | Хичээлийн урьдач нөхцөл          | Заримыг үзсэн           | Оюутан олон урьдач хичээлээс зөвхөн заримыг нь үзсэн              |
| 11  | Хичээлийн урьдач нөхцөл          | Урьдач нөхцөлгүй        | Хичээлийн `prerequisites` массив хоосон                           |
| 12  | Хүсэлтийн талбарууд              | Бүрэн                   | `studentID`, `courseID` талбарууд өгөгдсөн                        |
| 13  | Хүсэлтийн талбарууд              | Талбар дутуу            | `studentID` эсвэл `courseID` талбарын аль нэг өгөгдөөгүй          |

### 3.6 Тестийн oracle болон бие даасан байдал

Тест бүрд дараах шалгалтуудыг хийнэ:

1. HTTP статус код хүлээгдэж буй утгатай тэнцүү эсэх.
2. JSON хариуны `result` талбар хүлээгдэж буй утгатай тэнцүү эсэх.
3. Амжилттай бүртгэлийн үед `registrationID` тоон утгатай эсэх.
4. Урьдач нөхцөлийн алдааны үед `missing` массив шаардлагатай хичээлийн кодыг агуулж байгаа эсэх.

Тест бүр өөрийн setup өгөгдлийг `PUT /students/:id`, `PUT /courses/:id` хүсэлтээр үүсгэнэ. Системд байхгүй оюутан эсвэл хичээлийг шалгах тохиолдолд тухайн өгөгдлийг зориудаар үүсгэхгүй. Ингэснээр тестүүд өмнөх тестийн үр дүнгээс хамаарахгүй.

`registrationID` нь сервер ажиллаж байх хугацаанд нэмэгддэг тул яг тогтсон утгыг шалгахгүй, зөвхөн тоон утгатай эсэхийг шалгана.
