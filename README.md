## 3. Тест дизайн — сонголт ба утгын хүснэгт

### 3.1 Тестлэх функц

`POST /registrations` API нь оюутныг хичээлд бүртгэх үйлдлийг гүйцэтгэнэ. Бүртгэл амжилттай болохын тулд оюутан системд бүртгэлтэй, идэвхтэй, сонгосон хичээл системд бүртгэлтэй, мөн хичээлийн урьдач нөхцөлийг хангасан байх шаардлагатай.

Тест дизайн хийхдээ API-ийн оролтын нөхцөлүүдийг сонголтуудад хувааж, сонголт бүрд төлөөлөх утга тодорхойлон, тэдгээрийн хослолоос тестийн спецификациуд гаргав.

### 3.6 Тестийн oracle болон бие даасан байдал

Тест бүрд дараах шалгалтуудыг хийнэ:

1. HTTP статус код хүлээгдэж буй утгатай тэнцүү эсэх.
2. JSON хариуны `result` талбар хүлээгдэж буй утгатай тэнцүү эсэх.
3. Амжилттай бүртгэлийн үед `registrationID` тоон утгатай эсэх.
4. Урьдач нөхцөлийн алдааны үед `missing` массив шаардлагатай хичээлийн кодыг агуулж байгаа эсэх.

Тест бүр өөрийн setup өгөгдлийг `PUT /students/:id`, `PUT /courses/:id` хүсэлтээр үүсгэнэ. Системд байхгүй оюутан эсвэл хичээлийг шалгах тохиолдолд тухайн өгөгдлийг зориудаар үүсгэхгүй. Ингэснээр тестүүд өмнөх тестийн үр дүнгээс хамаарахгүй.

`registrationID` нь сервер ажиллаж байх хугацаанд нэмэгддэг тул яг тогтсон утгыг шалгахгүй, зөвхөн тоон утгатай эсэхийг шалгана.

## 4. Newman ашиглан автомат тест ажиллуулсан үр дүн

### 4.1. Тест ажиллуулах орчин

Postman Collection-ийг Newman ашиглан командын мөрөөс ажиллуулж, API-ийн автомат тестийн үр дүнг шалгасан.

Тест ажиллуулахын өмнө `localhost:3000` хаяг дээр API серверийг ажиллуулсан.

Үр дүнг файлд хадгалж, терминал дээр зэрэг харуулах команд:

```bash
mkdir -p results
set -o pipefail
newman run lab05-collection.json 2>&1 | tee results/newman-pass.txt
status=${PIPESTATUS[0]}
echo "Exit code: $status" | tee -a results/newman-pass.txt
```

### 4.2. Newman туршилтын үр дүн

Postman Collection-ийг Newman ашиглан ажиллуулж, нийт 12 тестийн тохиолдол, 27 хүсэлт болон 30 assertion-ийг шалгасан.

| Үзүүлэлт            | Pass | Fail | Server down |
| ------------------- | ---: | ---: | ----------: |
| Requests executed   |   27 |   27 |          27 |
| Requests failed     |    0 |    0 |          27 |
| Assertions executed |   30 |   30 |          30 |
| Assertions failed   |    0 |    1 |          30 |
| Exit code           |    0 |    1 |           1 |

- **Pass:** Бүх 30 assertion амжилттай биелсэн.
- **Fail:** TC-01-ийн хүлээгдэж буй статусыг зориудаар `200` болгосон боловч API `201` буцаасан тул нэг assertion амжилтгүй болсон.
- **Server down:** API сервер ажиллахгүй үед 27 хүсэлт `ECONNREFUSED` алдаа авсан бөгөөд 30 assertion амжилтгүй болсон.

Бодит үр дүнг дараах файлуудад хадгалсан:

- `results/newman-pass.txt`
- `results/newman-fail.txt`
- `results/newman-down.txt`

### 4.4. Assertion-ийн алдааг илрүүлсэн нь

`lab05-collection-fail.json` дээр TC-01 тестийн хүлээгдэж буй HTTP статусыг зориуд `200` гэж тохируулсан. API бодитоор `201 Created` буцаасан тул нэг assertion амжилтгүй болж, Newman `Exit code: 1` буцаасан. Энэ нь assertion-ийн хүлээгдэж буй үр дүн бодит үр дүнтэй зөрөхөд тест алдааг илрүүлж байгааг харуулсан.

### 4.5. Server down туршилт

API серверийг зогсоосны дараа Collection-ийг ажиллуулахад хүсэлтүүд `127.0.0.1:3000` хаягт холбогдож чадаагүй бөгөөд `ECONNREFUSED` алдаа гарсан. Нийт 27 хүсэлт холболтын алдаатай болж, 30 assertion амжилтгүй болсон.

Энэ нь буруу API хариу авсан тохиолдлоос ялгаатай бөгөөд сервер холболт хүлээн аваагүйг илэрхийлнэ.

### 4.6. DeprecationWarning

Newman ажиллуулах үед Node.js-ийн `fs.F_OK` ашиглалт хуучирсан тухай `DEP0176` анхааруулга гарсан. Энэ нь дангаараа тест амжилтгүй болсныг илэрхийлэхгүй. Pass туршилтын логт 30 assertion амжилттай биелж, exit code `0` гарсан.

## 5. Ерөнхий дүгнэлт

Энэхүү лабораторийн ажлаар Postman ашиглан `POST /registrations` API-ийн 12 тестийн тохиолдлыг боловсруулж, шалгасан. Тестүүдэд амжилттай бүртгэл үүсгэх, оюутан болон хичээл байхгүй байх, оюутан идэвхгүй байх, урьдач нөхцөл хангагдаагүй байх болон хүсэлтийн шаардлагатай талбар дутуу байх зэрэг нөхцөлийг хамруулсан. Тест бүрийн үр дүнг HTTP статус код болон JSON хариуны `result` талбараар шалгаж, урьдач нөхцөлийн алдааны мэдээлэл болон `registrationID` талбарын төрлийг мөн баталгаажуулсан.

Newman ашиглан 27 хүсэлт, 30 assertion бүхий автомат туршилтыг ажиллуулж, үндсэн тестийн цуглуулгад бүх assertion амжилттай биелснийг баталгаажуулсан. Зориуд буруу oracle ашигласан туршилтаар assertion-ийн алдааг илрүүлж, хүлээгдэж буй статус кодыг зөв тохируулсны дараа тестийг дахин шалгасан. Мөн сервер ажиллахгүй үеийн туршилтаар `ECONNREFUSED` холболтын алдаа болон API-ийн хариутай холбоотой assertion-ийн алдааг ялган ойлгосон.

Эцэст нь туршилтын үр дүнг `newman-pass.txt`, `newman-fail.txt` болон `newman-down.txt` лог файлд хадгалсан. Ингэснээр API-ийн хэвийн ажиллагаа болон алдааны нөхцөлийг шалгах, автомат тестийн үр дүнг харьцуулах, дахин нягтлах чадвар эзэмшсэн.
